# Brief Gamma. R2M7. Proves, depuració i checkpoint tècnic

## RA avaluat

- **RA avaluat**: `RA4`
- **CA avaluats**: `RA4.f`
- **RA de context**: cap

Este microrepte genera nota només per al RA avaluat. Els RA de context poden aparéixer en el producte, però no es ponderen en esta rúbrica.


## Objectiu

Crear o actualitzar una presentació de microrepte per a `R2M7`, centrada a convertir les comprovacions manuals de `R2M4`-`R2M6` en una prova HTTP executable, depurar incidències i deixar una demo reproduïble.


## Contingut que ha d'incloure

- Codi del microrepte: `R2M7`.
- Sessió associada: `R2S7`.
- Per què provar no és només fer una demo del camí feliç.
- Recorregut automàtic obligatori: accés protegit sense autenticar denegat, login incorrecte, login correcte, operació protegida permesa, logout i nova denegació.
- Com registrar entrada, passos, resultat esperat, resultat real i incidència.
- Diferència entre prova manual, prova de flux i prova unitària de `R2M8`.
- Lliurable: `tests/flux-r2.php` o prova HTTP equivalent en Bash, Python o Java.
- PHP CLI i extensió cURL: peticions, codi HTTP, cookies o token, temporals i neteja.
- Assercions sobre codis, redireccions o textos estables, amb codi d'eixida diferent de `0` quan falla.
- Una ordre documentada i eixida real en `evidence/r2m7/verificacio.txt`.
- Exemples:
  - ruta protegida sense sessió retorna denegació;
  - login correcte permet una operació protegida;
  - formulari invàlid mostra error.
- Errors habituals: `curl` que només imprimix, col·lecció sense assercions, pèrdua de cookies, script que sempre passa, README desactualitzat i confusió amb PHPUnit.
- Checklist final.

## Límit

No demanar proves unitàries, `PHPUnit`, mocks ni suite formal com a mínim. Sí que cal el recorregut HTTP complet amb comprovacions automàtiques; un únic `curl` sense asserció no és suficient.
