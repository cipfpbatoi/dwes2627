# R3M1. Arrencada del nou projecte

## En una frase

Deixa una base real en framework que una altra persona puga arrancar i explica
quins dos fluxos reconstruiràs durant `R3`.

## Visor del microrepte

| Camp | Valor |
|---|---|
| Repte | `R3` |
| Sessió | `R3S1` |
| Microrepte | `R3M1` |
| RA avaluat | `RA5` (`RA5.a`–`RA5.e`) |
| Autocorrecció | `r3-s01-arrencada-nou-projecte` |
| Producte | Framework arrancable, ruta mínima i abast dels dos fluxos |

## Punt de partida

Partixes del projecte funcional d'`R2`, però no has de copiar-lo sencer dins del
framework. Tria una acció real que valga la pena reconstruir i un segon flux
relacionat. Un dels dos ha de vindre clarament d'`R2` i almenys un serà
server-rendered amb HTML generat pel framework.

## Mínim obligatori

- Projecte en `Laravel`, `Symfony`, `Django` o `NestJS`, o via excepcional
  autoritzada.
- Docker, Compose o entorn equivalent amb instruccions reproduïbles.
- `.env.example` o instruccions de configuració sense secrets reals.
- Una ruta inicial, portada mínima o `healthcheck` gestionat pel framework.
- Comparació curta del stack triat amb una alternativa.
- Mapa abans/després entre les responsabilitats d'`R2` i les d'`R3`.
- Dos casos d'ús menuts i viables, indicant quin ve d'`R2` i quin serà
  server-rendered.

## Passos de treball

1. Tria el framework i escriu per què ajuda el teu projecte: plantilles, ORM,
   validació, proves o separació de responsabilitats.
2. Crea el projecte dins del repositori. No deixes el codi font fora de Git.
3. Prepara l'arrencada reproduïble i la configuració d'exemple.
4. Implementa una ruta mínima que responga realment des del framework.
5. Localitza la ruta, el controlador/view/manejador i la resposta o plantilla.
6. Dibuixa el mapa `R2 → R3`: entrada, coordinació, dades, regles i presentació.
7. Declara els dos casos d'ús i retalla'ls fins que siguen demostrables.
8. Prova l'arrencada seguint només les instruccions escrites.

## Què has de poder mostrar

```text
configuració local → arrencada → ruta del framework → resposta visible
```

- L'ordre exacta d'arrencada.
- La URL i la resposta obtinguda.
- El fitxer on es declara la ruta i la peça que prepara la resposta.
- La comparació de stack, el mapa `R2 → R3` i els dos fluxos.

## Evidències mínimes

| Evidència | Què ha de demostrar |
|---|---|
| `README.md` | Requisits, configuració, arrencada i URL de prova |
| Configuració d'exemple | Variables necessàries sense secrets personals o reals |
| Codi del framework | Ruta inicial i recorregut recognoscible |
| Documentació R3M1 | Comparació, mapa abans/després i dos casos d'ús |
| Resultat executat | Servei arrancat i resposta real de la ruta |
| Traçabilitat | Commits i registre d'IA si n'hi ha hagut |

## Comprova-ho abans d'entregar

1. Prepara una còpia neta o una situació equivalent.
2. Crea la configuració local a partir de l'exemple.
3. Executa l'ordre documentada.
4. Obri la ruta inicial amb navegador o `curl`.
5. Explica el recorregut sense llegir una resposta generada.

## Què no és suficient

- Instal·lar dependències sense poder arrancar.
- Una pàgina HTML oberta directament i no servida pel framework.
- Documentar una carpeta del projecte que no està versionada.
- Comparar frameworks de manera genèrica sense una decisió pròpia.
- Declarar “migraré tot R2” sense dos fluxos concrets.
- Versionar `.env`, claus, tokens o contrasenyes reals.
- Aportar només una captura sense instruccions reproduïbles.

## Ampliació opcional

- Prova HTTP automàtica de la ruta inicial.
- `healthcheck` del contenidor.
- Segona forma d'arrencada ben documentada.

## Fora d'abast

Encara no cal BBDD del domini, migracions, seeders, formularis complets,
autenticació ni API.
