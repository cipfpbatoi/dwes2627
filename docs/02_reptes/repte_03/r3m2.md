# R3M2. Persistència mínima amb migracions i dades reproduïbles

## En una frase

Crea una BBDD real que es puga reconstruir des de zero, carrega dades
recognoscibles i usa-les en una resposta de l'aplicació.

## Visor del microrepte

| Camp | Valor |
|---|---|
| Repte | `R3` |
| Sessió | `R3S2` |
| Microrepte | `R3M2` |
| RA avaluat | `RA6` (`RA6.a`–`RA6.e`) |
| Autocorrecció | `r3-s02-persistencia-minima-migrations-seeders` |
| Producte | Esquema versionat, dades inicials i lectura ORM integrada |

## Què heretes d'R3M1

- El framework i l'entorn ja arranquen.
- Els dos casos d'ús ja estan decidits.
- El model ha de preparar eixos fluxos, no totes les possibilitats futures.

Si R3M1 encara no arranca des de les instruccions, recupera primer eixe mínim.

## Mínim obligatori

- Connexió a una BBDD real configurada amb variables d'entorn.
- Models o entitats del domini estrictament necessaris.
- Migracions versionades o mecanisme equivalent.
- Claus foranes, unicitat o restriccions simples quan eviten dades impossibles.
- Fixtures, seeders o script de càrrega reproduïble.
- Dades recognoscibles relacionades amb els dos fluxos.
- Consulta real amb ORM o capa de dades.
- Llistat, detall, filtre o resposta que use eixa consulta.
- Ordres per reconstruir i carregar des d'una BBDD buida.

## Passos de treball

1. Escriu quines entitats, camps i relacions necessiten els dos fluxos.
2. Elimina del disseny allò que encara no s'usarà.
3. Configura la connexió sense escriure secrets al repositori.
4. Crea els models i genera les migracions amb les eines del framework.
5. Prepara dades inicials suficients per distingir casos i errors futurs.
6. Documenta la seqüència de reset, migració i càrrega.
7. Consulta les dades des de l'aplicació i passa-les a una vista o resposta.
8. Canvia una dada i comprova que també canvia la resposta visible.

## Cadena que has de demostrar

```text
BBDD buida → migracions → dades inicials → consulta ORM → resposta amb dades
```

Una consulta en shell pot ajudar-te a depurar, però no substituïx la lectura
integrada en una ruta real.

## Evidències mínimes

| Evidència | Què ha de demostrar |
|---|---|
| Configuració | Connexió funcional sense secrets versionats |
| Models i migracions | Esquema propi del domini creat des de zero |
| Fixture/seeder/script | Dades recognoscibles i reproduïbles |
| Ordres executades | Reset, migració i càrrega amb resultat real |
| Lectura integrada | Consulta real usada en llistat, detall, filtre o resposta |
| Documentació | Quines dades prepara cada flux i com reproduir-les |
| Traçabilitat | Commits i registre d'IA si correspon |

## Casos de comprovació

1. BBDD buida: les migracions creen l'esquema sense passos manuals.
2. Càrrega inicial: apareixen el recompte i les dades esperades.
3. Repetició: saps si el seeder és idempotent o si exigix una base buida.
4. Lectura web: la resposta mostra les dades de la BBDD.
5. Canvi real: en modificar una dada, la resposta també canvia.

## Què no és suficient

- Comptar només les taules internes del framework.
- Crear taules manualment amb phpMyAdmin, DBeaver o una eina semblant.
- Tindre models sense migracions versionades.
- Un seeder buit o dades introduïdes només a mà.
- Mostrar un array fix escrit al controlador o a la plantilla.
- Consultar en consola i no usar les dades dins de l'aplicació.
- Documentar ordres que no s'han executat.

## Ampliació opcional

- Una relació addicional que s'use realment.
- Factory per preparar proves aïllades.
- Prova automàtica de reconstrucció, càrrega o lectura.

## Fora d'abast

Encara no cal el formulari complet, els dos fluxos acabats, autenticació, rols
ni API. Tampoc cal modelar totes les taules imaginables del producte.
