# R3M7. Tancament tècnic

## En una frase

Deixa el projecte reproduïble i defensable: una altra persona ha de poder
arrancar-lo, reconstruir-lo, provar-lo i entendre què queda per a `R4`.

## Visor del microrepte

| Camp | Valor |
|---|---|
| Repte | `R3` |
| Sessió | `R3S7` |
| Microrepte | `R3M7` |
| RA avaluat | `RA5` (`RA5.f`, `RA5.g`) |
| Autocorrecció | `r3-s07-tancament-tecnic` |
| Producte | README reproduïble, demo, decisions i backlog cap a R4 |

## Punt de partida

No afiges funcionalitat gran. Treballes sobre l'aplicació estabilitzada d'R3M6
i comproves que la documentació descriu el codi real, no el projecte ideal.

## Prova principal de tancament

Imagina una còpia neta del repositori. Amb només els fitxers versionats i el
`README.md`, una altra persona ha de poder:

1. preparar `.env` sense inventar variables;
2. arrancar els serveis;
3. reconstruir la BBDD;
4. carregar usuaris i dades demo;
5. executar el primer flux i el seu error;
6. actualitzar i eliminar un recurs, inclòs un error d'R3M4;
7. provar convidat, usuari autoritzat i usuari denegat;
8. executar les proves o la checklist final.

## Contingut mínim del README final

- Requisits previs.
- Preparació de `.env`, sense secrets reals.
- Ordres d'arrencada i parada.
- Migracions, reset i càrrega inicial.
- Usuaris demo i credencials didàctiques.
- Descripció i passos dels dos fluxos.
- Component i manteniment d'R3M4.
- Acció protegida i regla d'autorització.
- Ordres de proves i resultats esperats.
- Decisions tècniques breus.
- Què s'ha migrat d'R2, què s'ha adaptat en R3 i què continua pendent.
- Primer recurs o endpoint candidat per començar R4.

## Mínim obligatori

- README que coincidix amb el projecte real.
- Configuració d'exemple completa i segura.
- BBDD reproduïble des de zero.
- Dos fluxos demostrables amb casos d'error.
- Acció protegida amb autoritzat i denegat.
- Ordres reals de proves o checklist final.
- Decisions tècniques i estat `migrat / adaptat / pendent`.
- Guió de demo de 5–7 minuts.
- Backlog concret cap a R4 sense implementar encara l'API.

## Guió recomanat de demo

1. Arrencada i reconstrucció de la BBDD.
2. Lectura inicial d'R3M2.
3. Cas positiu i error d'R3M3.
4. Component, actualització, eliminació i error d'R3M4.
5. Canvi d'usuari: autoritzat i denegat d'R3M5.
6. Suite o checklist final d'R3M6.
7. Decisió de continuïtat cap a R4.

## Evidències mínimes

| Evidència | Què ha de demostrar |
|---|---|
| README | Una altra persona no ha d'inventar passos |
| Configuració | Variables completes, sense secrets reals |
| BBDD | Reset, migracions i dades demo reproduïbles |
| Fluxos | Passos i errors que coincidixen amb el codi actual |
| Accés | Login, acció protegida, autoritzat i denegat |
| Proves | Ordres i resultats reals |
| Decisions | Stack, persistència i repartiment de responsabilitats |
| Estat | Diferència honesta entre migrat, adaptat i pendent |
| Backlog R4 | Un primer recurs/endpoint candidat i justificat |

## Què no és suficient

- Mantindre el README genèric del framework.
- Captures sense ordres reproduïbles.
- Dependència de fitxers locals no versionats.
- No explicar BBDD o dades demo.
- Presentar com a acabat allò que continua pendent.
- Preparar una demo que només funciona en l'ordinador de l'autor.
- Implementar l'API d'R4 en lloc de tancar R3.

## Ampliació 9→10

Només després de tancar el nucli, declara l'ampliació en
`docs/r3-ampliacio.md`. Ha de tindre commit identificable, decisió tècnica,
prova i demo. No compensa fluxos incomplets ni documentació fictícia.

## Fora d'abast

No implementes encara l'API d'R4, integracions externes, desplegament productiu
ni funcionalitats grans noves.
