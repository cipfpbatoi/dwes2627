## Producte mínim esperat

Un tancament tècnic honest i reproduïble. Amb una còpia neta, una altra persona ha de poder arrancar el projecte, reconstruir la BBDD, carregar dades, provar els dos fluxos, comprovar l'acció protegida i executar les proves o checklist.

El README final ha de coincidir amb el codi real i diferenciar:

- què s'ha migrat d'R2;
- què s'ha adaptat o ampliat en R3;
- què continua pendent;
- quin recurs o endpoint és candidat per començar R4.

## Criteris i pesos

| Dimensió | Pes | Què es comprovarà |
|---|---:|---|
| Resolució funcional | `50%` | Projecte arrancable, BBDD reproduïble i dos fluxos demostrables. |
| Verificació | `10%` | Instruccions provables d'arrencada, reconstrucció de BBDD, càrrega inicial i fluxos. |
| Traçabilitat | `5%` | Commits finals, decisions i backlog. |
| Documentació | `10%` | `README.md` amb arrencada, BBDD, fluxos, protecció d'accessos, demo i pas a `R4`. |
| Ús d'IA | `5%` | Verificació del text generat si s'ha usat IA. |
| Qualitat tècnica | `20%` | Tancament honest: migrat, ampliat, pendent i base defensable. |

## Evidències requerides

| Evidència | Mínim acceptable | Senyal esperat |
|---|---|---|
| README | Requisits, `.env` i arrencada | Una altra persona no ha d'inventar passos. |
| BBDD | Reset, migracions i càrrega | Es pot reconstruir des de zero. |
| Flux 1 | Passos del cas positiu i error | Coincidix amb R3M3 real. |
| Flux 2 | Passos, regla i error | Coincidix amb R3M4 real. |
| Accés | Usuaris demo, login i acció protegida | Inclou autoritzat i denegat. |
| Proves | Ordres o checklist final | El resultat és repetible. |
| Decisions | Notes breus i concretes | Justifiquen stack, persistència i responsabilitats. |
| Estat | Migrat/adaptat/pendent | No presenta com a acabat allò que falta. |
| Demo | Guió de 5–7 minuts | Mostra valor, error, BBDD i protecció. |
| Backlog R4 | Primer recurs/endpoint candidat | Prepara R4 sense implementar-lo encara. |

## Comprovació reproduïble

Des d'una còpia neta:

1. Prepara `.env` segons el README.
2. Arranca els serveis.
3. Reconstruïx i carrega la BBDD.
4. Executa el primer flux i el seu error.
5. Executa el segon flux i el seu error.
6. Prova convidat, usuari autoritzat i usuari denegat.
7. Executa proves o checklist.
8. Comprova que backlog i decisions descriuen el codi actual.

## Què no és suficient

- README genèric del framework.
- Captures sense ordres reproduïbles.
- Instruccions que depenen de fitxers locals no versionats.
- No documentar BBDD o dades demo.
- Ocultar parts pendents o afirmar una migració total inexistent.
- Preparar una demo que només funciona amb l'estat personal de l'autor.
- Implementar l'API d'R4 en lloc de tancar R3.

## Regles que limiten la valoració

- Sense README o instruccions d'arrencada, la puntuació màxima recomanada és `6`.
- Sense documentació de BBDD i càrrega, la màxima recomanada és `7`.
- Sense dos fluxos descrits/demostrables, la màxima recomanada és `7`.
- Sense backlog o continuïtat, la màxima recomanada és `8`.
- Si falta la protecció d'accessos en la documentació, es penalitzen documentació i qualitat.
- Si el README no coincideix amb el codi, cal revisió docent.

## Fora d'abast

No s'ha d'implementar encara l'API de `R4`.

Tampoc cal desplegament productiu, integracions externes ni funcionalitats grans noves.

## Ampliació opcional del repte complet

R3M7 recull la proposta separada de l’ampliació de R3, de 0 a 1. No suma a les dimensions del microrepte. El professorat la valida en la presentació segons la [regla comuna](../../ampliacions-excellencia.md#calcul-i-validacio-de-lampliacio-global). Declaració: `docs/r3-ampliacio.md`.

L'ampliació només es revisa quan el nucli anterior està complet. Ha d'incloure commit identificable, decisió, prova i demo; no compensa un README fictici, una BBDD no reproduïble o fluxos incomplets.
