    R3M4. Components de vista i manteniment d'un recurs¶

    En una frase¶

    Reutilitza una peça de vista i mantín un recurs existent amb PATCH/PUT, DELETE, BBDD coherent, errors controlats i regressió d'R3M3.

    Visor del microrepte¶

    Camp Valor
    Repte R3
    Sessió R3S4
    Microrepte R3M4
    RA avaluat RA8 (RA8.f, RA8.g)
    Autocorrecció r3-s04-segon-cas-us-ampliacio-funcional
    Producte Component reutilitzat, actualització i eliminació controlada

    Què heretes d'R3M3¶

    • Un recurs real que es pot crear o consultar.
    • Models, migracions i BBDD funcionals.
    • Validació, CSRF i resposta server-rendered.
    • Una prova positiva i una negativa del primer flux.

    R3M4 no és començar un CRUD complet ni copiar el formulari d'alta amb un altre nom. Has de treballar sobre un recurs existent i conservar el que ja funciona.

    Primer decidix tres coses¶

    Abans de programar, escriu:

    1. Recurs: què mantindràs —reserva, llibre, incidència, producte, torneig…—.
    2. Actualització: quins camps es poden modificar i per què usaràs PATCH o PUT.
    3. Eliminació: quan es pot eliminar i quina regla impedirà almenys un DELETE no vàlid.

    Cancel·lar, completar, arxivar o confirmar sol ser un canvi d'estat amb PATCH, no una eliminació. DELETE significa que el recurs deixa d'existir.

    Mínim obligatori¶

    • Component, parcial, macro, include o equivalent amb dades d'entrada clares.
    • La mateixa peça renderitzada en almenys dos contextos reals.
    • Formulari o recorregut d'edició d'un recurs existent.
    • PUT/PATCH o equivalent server-rendered documentat.
    • Validació de servidor, CSRF i valors conservats davant d'error.
    • DELETE o equivalent documentat.
    • Regla de domini que impedisca una eliminació no permesa.
    • 404 o resposta equivalent per a identificador inexistent.
    • Resposta basada en l'estat llegit novament de la BBDD.
    • Transacció quan una operació modifica diversos registres relacionats.
    • Proves d'actualització, error, eliminació i regressió d'R3M3.

    Component de vista: què compta¶

    Framework Equivalent adequat
    Laravel Component Blade anònim o de classe amb propietats explícites
    Symfony Component Twig, macro o include amb dades explícites
    Django 6+ partialdef i partial
    Django 5.2 o anterior include ... with ... only; inclusion_tag si cal lògica Python
    NestJS server-rendered Parcial o component del motor de plantilles

    Exemples útils: targeta o fila del recurs, etiqueta d'estat, resum d'errors, grup d'accions o camps compartits entre alta i edició.

    No compta el layout general. Tampoc compta copiar el mateix HTML en dos fitxers ni limitar-se a repetir un fragment dins d'un bucle sense usar-lo en dos contextos de la interfície.

    Recorreguts que has de construir¶

    GET /recursos/{id}/editar
  → recupera el recurs o retorna 404
  → mostra les dades actuals

PATCH /recursos/{id}
  → CSRF + validació + regla
  → actualitza la BBDD
  → redirigix i torna a llegir el resultat

DELETE /recursos/{id}
  → CSRF + recurs o 404 + regla d'eliminació
  → elimina o denega sense deixar canvis parcials

    Adapta les URLs i la convenció server-rendered al teu framework. Si l'HTML envia POST amb method override, documenta la correspondència.

    Proves mínimes¶

    Cas Què has de comprovar
    Component La mateixa peça apareix en dos contextos amb dades reals
    Actualització correcta Canvia el recurs i la BBDD conté el valor esperat
    Actualització invàlida Mostra l'error i la BBDD no canvia
    Eliminació correcta El recurs permés deixa d'existir
    Eliminació denegada La regla conserva el recurs i mostra un error
    Identificador inexistent 404 o resposta equivalent controlada
    Operació múltiple Una fallada provoca rollback
    Regressió El flux complet d'R3M3 continua funcionant

    Evidències mínimes¶

    • Component i els dos llocs on es renderitza.
    • Rutes i manejadors d'edició, actualització i eliminació.
    • Resultat executat dels casos de prova anteriors.
    • Comprovació de BBDD després d'actualitzar, denegar i eliminar.
    • Explicació de PATCH/PUT, DELETE, regla i transacció si aplica.
    • Commits, documentació i registre d'IA si correspon.

    Què no és suficient¶

    • Comptar el layout com a component nou.
    • Duplicar HTML en dos fitxers.
    • Canviar dades amb GET.
    • Fer només una transició d'estat i no cap DELETE real.
    • Anomenar PUT una actualització parcial sense justificar-ho.
    • Eliminar sense CSRF o sense regla de domini.
    • Modificar diverses files sense controlar la consistència.
    • No tornar a provar R3M3.

    Ampliació opcional¶

    • Variants o slots justificats del component.
    • Soft delete si el domini necessita conservar traçabilitat.
    • Prova específica de concurrència o rollback.

    Fora d'abast¶

    No toca encara API, integració externa, autenticació nova, rols complexos ni una biblioteca genèrica de components. No cal un CRUD complet.
